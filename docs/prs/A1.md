## Build

- The one frame type: buffers given once, then per-frame entries with identity (u64), plane layout, timestamps, and which memory the buffers live in (host, memfd, dmabuf, GPU).
- One pool. A pool miss never zero-fills. No `Arc` allocation per frame for external buffers; no clone of layouts or metadata per share.
- Read-only shares; writes only while sole owner. dmabuf CPU access brackets (sync start/end).
- Counts copies where they happen (a copy counter per site), so a test can assert zero.
- no_std + alloc core with a `std` feature.
- Timestamps are `CLOCK_MONOTONIC` nanoseconds, stated in the type's docs.

## Proof

Tests: a steady-state loop of 10,000 frames with a counting allocator shows 0 allocations and 0 copies after warm-up; share/hold/release order; no_std build on both MCU targets.
